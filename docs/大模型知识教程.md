## 0. 世界观：所有神经网络都是"张量流经参数矩阵"

一个训练好的模型 = 一组张流水（中间结果）+ 一组参数矩阵。ModelForge 画布上每条连线就是一条张量流，每个节点就是一次"用参数矩阵变换它"。

最底层只有三种零件：

| 零件 | 作用 | 本项目算子 |
|---|---|---|
| **线性变换** | y = xW + b，改变最后一维的大小 | `Linear`（ops.py:248） |
| **激活函数** | 引入非线性，否则叠多少层都等价于一层 | `ReLU / GELU / SiLU / Tanh / Sigmoid` |
| **归一化** | 稳定数值分布，让深网络训得动 | `LayerNorm / RMSNorm / BatchNorm` |

 Dropout 不算独立零件，它只是训练期的"噪声开关"。

**动手热身（MNIST 手写数字 MLP）**：
1. 画布空白双击（或看左侧固定节点）确认模型输入/输出端口。
2. 输入端口：`dtype=float32，shape=[batch, 1, 28, 28]`。拖 `Flatten`（start_dim=1）→ `Linear(784→128)` → `ReLU` → `Linear(128→10)`，输出端口 `shape=[batch, 10]`。
3. 右侧绿色"校验通过"徽标亮起后，工具栏「生成代码」看 `model.py` 的前向传播——你会看到 `x.view(batch, 784)` 式的展平和两次矩阵乘。
4. 训练：选 MNIST，几个 epoch 就能到 90%+ 准确率。

这个模型里藏着后面一切章节数字教学的基础：**参数量计算**。`Linear(784→128)` 的参数 = 784×128 + 128 = 100,480。记住公式 `in×out + out`，附录 A 会把它变成"读懂 LLM 规模"的工具。

## 1. 从词到向量：Embedding 与形状哲学

**为什么需要 Embedding**：语言模型的输入是词元 id（整数），`Linear` 对整数没有意义。`Embedding(num_embeddings=词表大小, embedding_dim=维度)`本质是**查表**：第 i 个 token id 直接取出表中第 i 行向量。数学上等价于"one-hot 向量 × 权重矩阵 W"，但查表比矩阵乘高效太多。

- 本项目算子：基础组 `Embedding`（ops.py:317），大模型组 `TokenEmbedding`（ops.py:756）——后者多一个"按 √d_model 缩放"选项，这是 2017 年原始 Transformer 论文的做法（让初始激活方差在不同 d_model 下大体一致；现代 LLM（LLaMA 等）通常去掉这个缩放）。

**形状哲学（本项目最重要的自动化校验）**：形状里的 `"batch"`、`"seq"` 是**符号维度**——`Embedding` 的形状规则（第 327 行）写着 `输出 shape = int64 输入的形状 + [embedding_dim]`，即 `[batch, seq] → [batch, seq, 768]`。符号维的意义：无论用户导入多长的序列，校验器都能推断出每层的形状，并在**连线时实时拒绝错配**（试试把 768 的端口连到 3072 的端口，看它回绝的理由）。这套逻辑在 `backend/app/ir/shapes.py`，是整个系统"教你看懂张量形状"的引擎。

**词表从哪来**：训练 text_cls 数据集时，生成脚本会构建一个简化词典（`<pad>=0，<unk>=1`，其余词按出现顺序编号），写进 run 目录的 `vocab.json`（generator.py:621）。推理时 `infer.py` 按同一个词典把文本变回 id。**真实大模型的差异点**：用的是 BPE/WordPiece 子词切分（几万词元即可覆盖无限文本、几乎无 `<unk>`），这不是注册表能画出来的东西，但链路思想一致：**文本 → id → 向量**。

**动手作业**：分别定义一个 `Embedding` 和一个 one-hot 等价的 `Linear`（in=词表大小），比较"生成代码"里两者 forward 的差别，理解"查表是 one-hot 矩阵乘的快速特例"。

## 2. 注意力：Transformer 的心脏

### 2.1 直觉：软性哈希检索

把每个 token 的向量 $x$ 经过三组不同的变换，得到三个身份：

- **Query（我想要什么）**
- **Key（我能提供什么）**
- **Value（我携带的信息）**

$$\text{Attention}(Q,K,V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

第一个矩阵乘 $QK^\top$ 算出"每个 token 对其他所有 token 的关注度"，softmax 把它归一化成概率行，再加权求和 V。这就是"上下文融合"：一个 token 的输出由**全序列的信息按相关度加权**而成。对比 `LSTM`（只能从左到右逐个传递、远距离信息一路衰减），注意力是**任意两点直连、一步到达**——这是 Transformer 淘汰 RNN 的根本原因，也让整个序列的计算可以**并行**（GPU 友好）。

### 2.2 √d_k 缩放与多头

- **为什么除以 √d_k**：维度越大，QK^\top 的点积数值方差越大，softmax 会变成"近乎 one-hot"，梯度几乎为零。除以 √d_k 把方差拉回 1 附近，softmax 保持"软"。
- **多头为什么需要**：一组 Q/K/V 只能表达一种"关注模式"（比如"主语找谓语"）。每组头在比完整的嵌入维小（768/8=96）的子空间里各自表达一种相关性——局部搭配、语法关系、远距离指代——**各司其职后拼接**，由输出投影 $W_O$ 混合。这就是为什么本项目的算子有个**属性校验：`embed_dim % num_heads == 0`**（ops.py:600 的 `_divisible`），填 768/8 成立，填 768/10 直接红字报错。

**本项目落点与诚实差异**：`MultiHeadAttention`（ops.py:582）是**自注意力**：forward 模板里 q=k=v=同一个输入（`{{in.x}} 传了三遍`）；`need_weights=False` 是个值得读懂的小工程优化（不返回注意力权重矩阵，省显存、走更快的内核路径）。它**没有 causal mask 参数**——这点在 §6 品解答"为什么本项目拼出来的 GPT 不是真 GPT"时会很关键。

### 2.3 双向 vs 单向：先记住这张图

对照算子 `LSTM` / `GRU`（ops.py:603/622）是"迟到的答案"：信息串行传递，`bidirectional=True` 时双向各跑一遍再拼。它们在 2024 年之前是 NLP 的主流，今天仍在 Streaming、轻量级任务出现。把"串行 vs 并行""步数 O(seq) vs O(1)"记进脑，后面理解 KV-Cache 的价值会一通百通。

## 3. 位置编码：给"无序的词袋"注入顺序

### 3.1 问题

自注意力对序列顺序是**置换等变**的——把"猫吃鱼"和"鱼吃猫"的三个向量随便洗牌，每个位置的输出还是同一组向量（只是跟着换了位置），所以必须**主动注入位置信息**。

本项目给了三代方案（这本身就是一个教学样本）：

1. **`PositionalEncoding`（ops.py:736）** 正弦或可学习：
   - 正弦（sinusoidal，2017 原版）：位置 p 的第 i 维 = sin/cos(p/λ_i)，**无需训练**、可外插；
   - 可学习（learned，BERT 风格）：`nn.Parameter(max_len, d_model)`，表达力强但**最长长度写死**（max_len）。
2. **`RoPE`（ops.py:641，helper 源码注入 `backend/app/registry/ops.py:944`）**：现代 LLM（LLaMA/Qwen/DeepSeek）的主流。核心思想：**不把位置加在输入上，而是把 Q/K 向量的分量两两配对做旋转**，旋转角度 θ_i = p · base^(−2i/d)。数学性质：两个位置 p₁、p₂ 经过旋转后的 QK^\top 点积**只依赖 p₁−p₂（相对位置）**——"绝对值方式注入，相对值方式起作用"，因此训练时没见过的长度下行为更稳顺。读一下 `RotaryEmbedding.forward`：`x1=x[...,0::2]、x2=x[...,1::2]`，余弦 sin 正弦公式逐对写出，这就是全部魔法。

**动手对照**：搭同一个 `TokenEmbedding → TransformerEncoderLayer` 结构，输入前分别串 `PositionalEncoding(sinusoidal)` 与 `RoPE`，各训练 text_cls 若干轮，比 val_acc 与 loss 曲线（数据集小，差距未必显著，重点是你要**能跑通两种**并指出各自注入的图层）。

## 4. Transformer Block：把零件拼成"层"

`TransformerEncoderLayer`（ops.py:663）内部 = 自注意力 + 前馈网络（FFN/MLP）+ 每步后的残差 + LayerNorm：

```
Post-LN（2017 原版）:  y = LN( x + Attn(x) );  z = LN( y + FFN(y) )
Pre-LN（现代主流）  :  y = x + Attn( LN(x) );  z = y + FFN( LN(y) )   ← GPT-2/LLaMA 系
```

四个"为什么"：

1. **为什么残差（`Add`，ops.py:570）**：梯度走 `y = x + f(x)` 时的恒等高速公路，上百层也能训；视觉界 ResNet 的 ResNetBlock（ops.py:826——注意：注册表把它归在"大模型模块"组，是个历史彩蛋，拆开看会发现"残差思想不属于语言也不属于视觉，属于深度学习本身"）。ResNetBlock 的 init 模板还有个值得读的细节：**当 stride≠1 或通道数变了，skip 分支用 1×1 卷积做形状适配**——残差在工业界的真实复杂度。
2. **为什么 FFN 是 4 倍宽（dim_feedforward=3072，d_model=768）**：先压扁升维到 4×，非线性激活，再投回。可以理解为"key-value 存储/一次大规模变换"，是参数量重镇（是注意力的 2 倍，见附录 A）。现代 MoE 就是把这层换成多个"专家"按 token 路由——方向已在 GPT-4/Mixtral 上验证。
3. **为什么 Pre-LN**：计算顺序 `x + f(LN(x))`（先归一化再进子层）。2019 年发现它让深网络不再需要精心的小学习率热身，**LLaMA 系就是 Pre-LN + 末尾一个总 RMSNorm**。对照老式的 Post-LN（先算再加再归一化）训练更容易抖。本项目 `nn.TransformerEncoderLayer` 内部是 Post-LN——看生成代码时可以找到这个差异。
4. **GELU vs ReLU**：GELU 用高斯 CDF 平滑了 ReLU 的硬边界，Transformer 栈事实标准；SiLU/Swish（x·σ(x)）是爆发门控（SwiGLU）的基元，LLaMA 的 FFN 用 SwiGLU（本项目 MLP 算子支持 activation=silu，你可以拼出一个"半个 SwiGLU"的实验）。

**`ViTBlock`（ops.py:794）是个活教材**：模板把 Pre-LN 写法**手工展开**了（看 ops.py:818-822 的 fwd 模板），你可以逐行对读"残差结构的两种书写"。它的 `mlp_ratio=4.0` 也呼应了 4× 惯例。

**动手作业（模块化的意义所在）**：用基础算子手工拼一个这样的子图并「保存为模块」：

```
x ─┬→ Linear(768→3072) → GELU → Linear(3072→768) ─→ Add ─→ LayerNorm ─→ y
   └─────────────────（Add 的第二个输入：从「进 FFN 之前」拉一条线）
```

（Add 是双输入算子：把"进 FFN 之前"的线拉一条到 Add。保存时定义好对外输入/输出端口。）然后在任意模型里拖入它并堆 3 层——**这就是"TransformerBlock 模块"在日常项目里的复用方式**，也是本项目 Graph IR 超越 ONNX 的地方（ONNX opset 没有"模块"这个概念）。

## 5. 三大家族与解码器：搞清 GPT/BERT/T5 的区别

| 家族 | 结构 | 代表 | 训练目标 |
|---|---|---|---|
| encoder-only | 双向自注意力 | BERT/RoBERTa | 完形填空（掩码重建） |
| **decoder-only** | **单向自注意力** | **GPT/LLaMA/Qwen/DeepSeek** | 预测下一个 token |
| enc-dec | 编码器（双向）+ 解码器（交叉注意力） | T5/BART | seq2seq（翻译/摘要） |

`TransformerDecoderLayer`（ops.py:684）带你参观 enc-dec 家族的结构差异：它有**两个输入端口**——`tgt`（解码端，走自注意力）和 `memory`（编码器输出，走**交叉注意力**：Q 来自 tgt，K/V 来自 memory）。用画布把一个编码子图的输出接进 `memory`，你就能直观看到"信息如何跨结构流动"。

### 5.1 causal mask：decoder-only 的命门（重要诚实声明）

真 decoder-only LM 在注意力里要加**下三角掩码**：位置 i 的 token 只能看 ≤ i 的位置，否则"预测下一个词"就成了作弊（答案已经放进上下文了）。**本项目的算子注册表没有掩码类算子**，所以你拼出的"TokenEmbedding → Rope → EncoderLayer × N → LMHead"是**双向**的——能训练、能跑、能生成代码，但它是"encoder 栈 + LM 头"，不是因果语言模型。这不是缺憾，是**教学钩子**：

**进阶练习（把这个项目变成真 LLM 实验室）**：按 `docs/拓扑Schema与算子贡献指南.md` 给 `ops.py` 加一条带 causal mask 的自定义算子（比如在 forward 模板里给 `nn.MultiheadAttention` 传一个下三角 `attn_mask` buffer），然后就能在画布上拼出真正的 GPT 块。走完这条练习你对"注册表 = 单一事实来源"的理解会从概念变成肌肉记忆。

`LMHead`（ops.py:775）把隐藏态映回词表 logits（768→32000，**这是参数量大头**，这些 logits 与 Embedding 是同一个概念轴）。前沿信息：几乎半数 LLM 把 LMHead 和 Embedding **权重绑缩（weight tying，同一矩阵复用）**——训练参数省一个词表大小。本项目没做绑定，读生成代码时值得作为思考题。

## 6. 训练回路：loss、优化器、验证集

工具栏「训练」触发时，后端把你的拓扑生成一个**可独立运行**的 `train.py` 并以子进程运行（`backend/app/training/jobs.py`），日志按行输出 JSON、以 SSE 流式推到前端（这就是你看到的实时滚动）。读 `TRAIN_PY_TPL`（generator.py:491 起）逐段对照：

- **选择损失**（generator.py:682）：回归任务用 `MSELoss`，分类任务用 `CrossEntropyLoss`。**坑点即考点**：`nn.CrossEntropyLoss` 吃原始 logits，内部**自带 log_softmax**——所以你的 MNIST MLP 最后一层**不要**再接 Softmax 算子（接了不会报错，但数学上等于做了两次 softmax，损失被抹平变平，训练效果会莫名糟。"logits vs 概率"是面试常客）。
- **优化器**：`Adam`（generator.py:683）。一阶动量 + 二阶动量除法让不同参数获得各自有效的步长——"为什么 Adam 万金油"一句话版。
- **训练/验证切分**：`random_split` 切 20% 做验证（generator.py:671）。**过拟合的判断就在这里**：train_loss 持续降、val_loss 先降后升的拐点就是你该停的地方（生成脚本按 val_loss 保存最优 checkpoint，generator.py:735，即"早停"思想）。
- **batch/epoch 的直觉**：batch 越大梯度估计越稳（显存 换质量）；epoch 是整体重复遍历。
- **多输出模型**只有 `--dataset random` 能训（generator.py:531 的 `check_classification_io` 会拒绝），**随机拟合数据集（random）是"万能冒烟数据集"**：它不关心任务是否有意义，只考察拓扑结构与梯度流是否通畅——新增复杂拓扑先在 random 上跑通，再换真任务。

**三套内置数据集的教学分工**：

| 数据集 | 输入/输出 | 教什么 |
|---|---|---|
| random | 任意 | 拓扑冒烟：只要校验通过就能训练 |
| mnist | float32 [b,1,28,28] → [b,10] | 图像分类主干路线 |
| text_cls | int64 [b,seq] → [b,2] | 文本路线：Embedding→主干→分类头 |

## 7. 推理回路：从 logits 到答案

「已训练模型」抽屉按 model_id 找到 run 目录，加载 `code/model.py + model.pt`（`backend/app/training/infer.py`），输入表单**自适应**模型 specs：

- int64 输入 + 有 vocab.json → 出**文本框**（文本→分词→id→padding）
- float32 形如 [..,1,28,28] → 出**图片上传**（灰度缩放 28×28）
- 其余 → 张量 JSON

对比训练回路理解两点：**推理是 `model.eval()` + `torch.no_grad()`**（Dropout 关闭、不建计算图）；分类输出是 logits →（softmax 后）概率——前端展示的是概率与 argmax。**生成式 LLM 的差距**：真实对话模型还有"自回归生成"——循环调用模型、每步把新 token 拼回输入、用温度/top-p 采样而非 argmax、并用 KV-Cache 缓存历史 K/V 避免重算。这些不是注册表能画的（都是"循环 + 采样策略"层面的算法），但当你理解了"模型本体只是一次 forward"，CodeGen 变得必要的原因就自然透明了。

## 8. 视觉支线：CNN → ResNet → ViT

- `Conv2d`（ops.py:288）：局部感受野 + 权重共享。形状公式 `(H+2p−k)/s+1`、池化、Flatten 的组合是图像主干的第一课。`padding=1, kernel=3` 的组合最常见（保持尺寸）。
- `ResNetBlock`（ops.py:826）：双卷积 + BN + 残差，skip 分支的 1×1 卷积做通道/步长适配。
- `ViTBlock`（ops.py:794）：把 ViT 标准块展开成了模板（Pre-LN 双残差 + MLP），也是一个可以逐行读的模板样本。
- **ViT 的"图片变序列"**：真实 ViT 用 kernel=stride 的大卷积把图片切成 patch token；本项目目前没有 Permute/Transpose 算子，严格 patch 化（含维重排）拼不出来——又是一个"扩展算子"练习（见贡献指南），或先用 Reshape（`[b, C, H, W] → Flatten 空间维 → Linear`）近似。
- **BatchNorm vs LayerNorm 必考题**：BN 在 batch 维上做统计（训练时依赖 batch、CNN 主流），LN 在特征维（每个 token 独立、与 batch 无关、Transformer 主流）。训练/推理行为差异（running stats）也是 BN 独有的坑。

## 9. LoRA 与参数高效微调（PEFT）

`LoRAAdapter`（ops.py:864）是一个完整的单文件教材，**三个设计决策一个都别错过**：

1. **低秩假设**：微调改变量 ΔW 是低秩的，用两个瘦矩阵的乘积表达：`down: 768→8`，`up: 8→768`。参数 2×768×8 = 12,288 ≈ 满矩阵 768² = 589,824 的 **2%**。
2. **up 零初始化**（ops.py:883 有注释）：初始 ΔW = B·A = 0，**加载即恒等**——不破坏原模型行为，训练从"零偏移"开始。这是"分布式训练侧 LoRA 加载无损"的工程根因。
3. **缩放 α/r**（默认 16/8=2）：让"秩"和"学习率"解耦，换 r 时不必重调 alpha。

forward 模板就是"并联式"写法本身：`y = x + (α/r)·up(down(x))`。真实 LoRA 有两种挂法：**串联式**（adapter 接在层输出之后）与**并联式**（如本模板；把 LoRAAdapter 与原层并联、再用 `Add` 合流，就是"用画布搭出了 adapter 电路"）。

**动手作业**：MNIST CNN 主干里接一个 LoRAAdapter，在 text_cls 上对比有无 LoRA 的 val_acc 和训练时长，然后读生成代码看 `down`/`up` 两层是如何被注入的。

## 附录 A：参数量速算（用本项目默认值体会 LLM 的体格）

以 d_model=768（GPT-2 small 的那个 768）为例：

| 组件 | 公式 | 数值 |
|---|---|---|
| Linear(d→d) | d² + d | ≈ 0.59M |
| MHA(Q,K,V,O 四个投影) | 4d² | ≈ 2.36M |
| MLP(4×FFN) | 8d² | ≈ 4.72M |
| **一个 Transformer 层** | ≈ 12d² | **≈ 7.1M** |
| Embedding(32k 词) | vocab×d | 24.6M |
| LMHead | d×vocab | 24.6M |

GPT-2 small 124M 参数的出处就有数了：12 层 × 7.1M ≈ 85M + 词表 38.6M（50257×768）≈ 124M。**层数换深度、词表占大头**——这就是"吞吐与 wholesale 的参数分布直觉"。

## 附录 B：常见校验报错翻译

| 报错场景 | 意思 | 处方 |
|---|---|---|
| "shape 不匹配（768 vs 3072）" | 两端口最后一维对不上（smoke 用例 2） | 查前一层 out_features 与当前层 in_features |
| "维度必须为偶数"（RoPE） | 旋转需要两两配对 | dim 填偶数 |
| " MLP: 最后一维=768 不符" | 拼接错层 | 确认进 FFN 前的形状 |
| " embed_dim % num_heads != 0" | 多头切不开 | 调头数或 embed_dim |
| "需要单输入单输出"（mnist/text_cls） | 数据集 IO 契约 | 用 random 数据集冒烟任意结构 |
